# "What If…" Video Studio — local setup + reusable prompt

This repository contains a code-only video studio: every frame, map, character, sound effect and music cue is
generated by Python. No stock footage, no paid services. This file has three parts:

- **Part 1:** one-time setup on your own PC (you do this).
- **Part 2:** the prompt to paste into Claude Code on your PC each time you want a new video (fill in the blanks).
- **Part 3:** reference: the episodes so far and which one to use as a template.

---

## Part 1 — One-time setup on your PC

You need about **3 GB free disk** (repo ~0.6 GB + render cache), **4+ CPU cores** recommended, and internet once
for installs. A 2:30 video takes roughly 15–30 minutes to render on 4 cores.

### 1. Install the tools

| Tool | Windows | macOS |
|---|---|---|
| Git | git-scm.com (includes **Git Bash**, which runs the `.sh` scripts) | `xcode-select --install` |
| Python 3.11–3.13 | python.org (tick **"Add python.exe to PATH"**) | python.org or `brew install python@3.12` |
| FFmpeg | `winget install Gyan.FFmpeg`, then open a new terminal | `brew install ffmpeg` |
| Claude Code | claude.ai/code → install for your OS (desktop app or CLI) | same |

Check in a new terminal: `git --version`, `python --version` (or `python3`), `ffmpeg -version`.

### 2. Get the project

```bash
cd ~/Documents            # or any folder you like, e.g. D:\Videos on Windows
git clone https://github.com/joe5408-sys/Joe-s-Training-Apps.git
cd Joe-s-Training-Apps
git checkout ccr-217bd17e-75ldp2      # the branch that holds the video episodes (until it is merged)
```

If the repository is private, Git will ask you to sign in to GitHub.

### 3. One shared Python environment

```bash
python -m venv .venv
# Windows (PowerShell):  .venv\Scripts\Activate.ps1
# Windows (Git Bash):    source .venv/Scripts/activate
# macOS / Linux:         source .venv/bin/activate
pip install numpy scipy opencv-python-headless pillow soundfile pyloudnorm pyshp
# only if you want a narrated (voice) video:
pip install kokoro-onnx faster-whisper
```

### 4. Open the folder in Claude Code

Open Claude Code **in the `Joe-s-Training-Apps` folder** and paste the prompt from Part 2.
The map cache (`build/tex`) and, for narrated videos, the voice model (~330 MB) are created automatically
on the first build — Claude Code will run those steps.

> Tip: keep renders off cloud-synced folders (OneDrive / iCloud / Google Drive). Rendering writes thousands
> of temporary files and syncing slows it down a lot.

## Part 2 — The prompt (copy everything inside the box, fill in the `[…]` parts)

```text
You are working in my local "What If…" video studio repository (this folder). Every visual and sound is
generated by Python code; nothing is downloaded or copied from other creators.

## The new video
- Title: [WHAT IF … ?]
- One-line premise: [e.g. "What if all the water on Earth vanished?"]
- Style template (pick one):
    A) Narrated history documentary with maps — template: what-if-sarawak-japanese-rule/
    B) Number cards + countdown + deadpan dark humour, no voice — template: what-if-hydrogen-vanished-v2/
    C) Atom-zoom QUIZ in a real place, low-poly 3D scene, no voice — template: what-if-oxygen-vanished-v3/
    D) Animated disaster scene with crowds/ships/explosions — start from C and extend the 3D engine (see "Animation" below)
  My choice: [A / B / C / D]
- Location shown on screen: [e.g. Kuching waterfront, Sarawak / Miri / none]
- Length: [2:00–3:00, aim 2:30]   Format: vertical 1080×1920, 30 fps, H.264 + AAC, MP4 under 100 MB
- Voice narration: [no / yes — British male synthetic voice, Kokoro "bm_george"]
- Audience: general public on TikTok / YouTube Shorts / Reels; plain English
- Tone: [serious documentary / deadpan dark humour / playful quiz]
- Must-include facts or questions: [list, or "you propose them"]

## How to work
1. Read the README.md and src/ of the template folder first. Copy the whole template folder to a NEW folder
   named what-if-<short-title>/ (copy assets/, src/, tools/, build.sh, requirements.txt, .gitignore;
   copy build/tex/ if it exists to save time). Never modify existing episode folders.
2. Detect my OS. On Windows use PowerShell or Git Bash paths correctly, use the .venv at the repo root,
   and run the build steps one by one if build.sh cannot run.
3. FIRST write the script (src/script.py) and a fact table with a source for every number, and SHOW ME
   both before rendering anything. Wait for my approval.
4. After approval: build the timeline, the soundtrack, test stills (contact sheets of ~1 frame per card that
   you look at yourself), fix problems, then the full render, then the 100 MB-limit delivery encode.
5. Deliverables in <folder>/output/: the MP4, a 1080×1920 thumbnail PNG, an .srt of all on-screen text
   (or narration), captions-and-timings.txt, assets-and-attribution.md (every figure with source or working),
   and a short README with rebuild commands.

## Accuracy and ethics (non-negotiable)
- Never present a guess as fact. Every number gets an on-screen badge: REAL DATA (published value),
  ROUGH ESTIMATE · OUR CALCULATION (show the working in the attribution file) or THOUGHT EXPERIMENT.
- Cite a real source for every REAL DATA figure (agency, paper or standard reference). If you are not sure
  a figure is right, say so and leave it out rather than inventing it.
- Recompute every estimate in code before using it; prefer "about / roughly" with honest ranges.
- History: separate ACTUAL HISTORY from ALTERNATE HISTORY on screen; no glorification; no real flags or
  symbols of perpetrator regimes; non-graphic depictions of suffering.
- People and violence: stylised, non-graphic (no blood or gore). Disasters shown through objects,
  particles, sound and numbers.
- Real places are "historically inspired / stylised illustrations" and must be labelled so.
- If I give a reference video for inspiration, take only the general idea. Do not copy its wording,
  caption style, layout, camera framing, music or characters; write all text from scratch and tell me what
  you changed.
- Explain things in simple English; I am a scientist, not a linguist.

## Animation (for style D, or whenever I ask for more motion)
The 3D engine is src/world3d.py (flat-shaded polygons, painter's sort, near-plane clipping) plus effects in
src/scenes.py. You may extend it with, for example:
- people with walk/run cycles, panic paths away from danger, crowds bunching at exits;
- ships and boats that roll, pitch, leave wakes, drift, collide or are lifted by a wave;
- explosions: flash, expanding shockwave ring, debris with gravity, rising smoke/dust (particles);
- water: rising flood plane, waves (height-field strips), splashes;
- camera moves: push-ins, shakes on impacts, slow motion with an on-screen clock.
Keep it non-graphic. Keep render time reasonable (check s/frame on stills first; target < 1.5 s/frame
on 4 cores) and tell me the expected render time before the full render.
If I ask for "much more realistic" animation, tell me the trade-off of switching to Blender (free, local,
Python-scriptable, far better visuals, much slower renders and a bigger setup) before doing it.

## Quality checks before you tell me it is done
- ffprobe: 1080×1920, 30 fps, H.264 High, AAC 48 kHz stereo, duration in range, file < 100 MB.
- ffmpeg freezedetect (no freeze > 2.5 s unless intended), silencedetect (no silence > 1.5 s unless intended),
  ebur128: about −14 LUFS, true peak ≤ −1 dBTP.
- Look at stills from the start, middle and end of the FINAL file: text inside the safe area
  (avoid the top ~230 px and bottom ~350 px for key text, and ~90 px at the sides), nothing clipped or overlapping.
- For narration: transcribe the final mix (tools/qa_transcribe.py / qa_sync.py) and report word errors and
  subtitle-sync offsets.
- Report honestly: what was checked, what is uncertain, and any limitation. Do not commit or push unless I ask.
```

How a build works (same in every folder):
`src/script.py` (content) → `src/timeline.py` (timings, SRT) → `src/audio.py` (music + effects; plus `src/tts.py`
for narration) → `src/render.py --workers 4` (frames → MP4) → `src/thumbnail.py` → FFmpeg mux and two-pass encode
(`build.sh` shows the exact commands). Test frames: `python src/render.py --stills 5,30,60`.

Known limits: the 3D look is simple low-poly; the voice is synthetic (check local pronunciations by ear);
renders are CPU-only.
